# SMART LIBRARY MANAGEMENT SYSTEM

1. PROJECT OVERVIEW

---

Smart Library Management System is a C++17-based library management
application designed to simulate the operations of a modern library.

The system supports:

* Book management
* Member management
* Student, Faculty, and Librarian roles
* Role-based access control
* Book borrowing and returning
* Book reservations
* Borrowing history
* Fine calculation based on member role
* Library statistics
* Exception handling
* Logging
* Interactive console-based application
* Automated testing using GoogleTest
* CMake-based build system

The project follows a layered design with core library logic,
service-layer operations, application/UI handling, and automated testing.

4. BUILD INSTRUCTIONS

---

Open PowerShell in the project root directory:

```
cd "{PATH}\Library_Management_System"
```

Configure the project:

```
cmake -S . -B build -G "MinGW Makefiles"
```

Build the project:

```
cmake --build build
```

If the project has already been configured and only source files
have changed, the following is normally sufficient:

```
cmake --build build
```

## 5. RUN THE APPLICATION

After a successful build, run the main application:

```
.\build\SmartLibraryApp.exe
```

The application starts the interactive Smart Library Management System.

The application provides role-based menus for:

* Librarian
* Student
* Faculty

Users can log in using their registered Member ID and perform operations
allowed for their role.

6. RUN AUTOMATED TESTS

---

The project uses GoogleTest for automated testing.

To run all CTest tests:

```
ctest --test-dir build --output-on-failure
```

Individual test executables can also be executed directly.

For example:

```
.\build\EndToEndTest.exe
```

To run a specific GoogleTest test:

```
.\build\EndToEndTest.exe --gtest_filter=EndToEndTest.OverdueBookGeneratesFine
```

## 7. END-TO-END TEST COVERAGE

The EndToEndTest suite verifies the major application workflows.

The current end-to-end scenarios include:

1. StudentCanBorrowBook
   Verifies that a student can successfully borrow a book.

2. FacultyCanBorrowBook
   Verifies that a faculty member can successfully borrow a book.

3. StudentCanReserveUnavailableBook
   Verifies that a member can reserve a book when no copies are available.

4. ReturningBookProcessesReservation
   Verifies that returning a book processes the reservation queue.

5. OverdueBookGeneratesFine
   Verifies that an overdue book generates the correct fine.

6. StatisticsReflectLibraryActivity
   Verifies that library statistics reflect borrowing activity.

7. CompleteLibraryWorkflow
   Verifies a complete borrowing, reservation, return, and statistics
   workflow.

8. UnauthorizedMemberCannotAddBook
   Verifies role-based access control for adding books.

9. UnauthorizedMemberCannotRemoveBook
   Verifies role-based access control for removing books.

10. InvalidOperationThrowsException
    Verifies that invalid library operations generate the appropriate
    exceptions.

11. HOW TO INTERPRET RESULTS

---

Successful application build:

```
[100%] Built target SmartLibraryApp
```

This means compilation and linking completed successfully.

Successful GoogleTest execution:

```
[  PASSED  ] 10 tests.
```

This indicates that all 10 configured end-to-end test scenarios passed.

Successful CTest execution normally reports:

```
100% tests passed, 0 tests failed out of ...
```

This means all tests registered with CTest completed successfully.

If a test fails, GoogleTest displays:

```
[  FAILED  ] TestName
```

The output immediately above the failure normally identifies the
assertion or exception that caused the failure.

Build errors should be investigated first if the executable cannot be
created.

Runtime exceptions should be investigated if the application builds but
terminates unexpectedly.

11. TROUBLESHOOTING

---

If CMake reports a generator mismatch, remove the existing build
directory and configure again:

```
Remove-Item -Recurse -Force build
```

Then:

```
cmake -S . -B build -G "MinGW Makefiles"
```

If compilation fails after modifying source files:

```
cmake --build build
```

If tests fail, run the individual test executable with a GoogleTest
filter to isolate the failing scenario:

```
.\build\EndToEndTest.exe --gtest_filter=TestSuite.TestName
```

For example:

```
.\build\EndToEndTest.exe --gtest_filter=EndToEndTest.OverdueBookGeneratesFine
```
